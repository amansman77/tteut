# ADR-PROD-002 Founder Seeder: 창업자 의미 입력 시스템을 먼저 만든다

## 상태
승인

## 맥락

뜨읏의 핵심 경험은  
"뜻을 발견하고 의미를 나누는 것"이다.

하지만 초기 서비스에는  
아직 살아낸 뜻이 존재하지 않는다.

즉,

- 보여줄 의미가 없고
- 공감할 문장이 없고
- 사용자가 참고할 기준도 없다

이 상태에서

"당신에게 존중은 무엇인가요?"

라고 묻는 것은  
빈 종이를 건네는 것과 같다.

사람은  
읽을 것이 있어야  
쓰기 시작한다.

따라서  
초기 문제는 사용자 유입이 아니라

> 어떻게 첫 의미(seed)를 심을 것인가

이다.

또한  
사전적 의미는 직접 관리하지 않는다.

표준국어대사전 Open API를 통해  
통용되는 의미를 가져오고,

뜨읏은 그 위에  
"살아낸 뜻"을 쌓는다.

## 결정

공개 사용자 UX보다 먼저  
**Founder Seeder 시스템**을 만든다.

창업자는 직접

- 단어를 고르고
- 살아낸 뜻을 입력한다

즉,

> 플랫폼은 사용자가 만드는 것이 아니라  
> 창업자가 먼저 심는 것이다

라는 원칙으로 시작한다.

질문과 태그는  
후속 사용자 경험에서 생성되며

초기 입력은  
오직 "살아낸 뜻"에만 집중한다.

## 구성

### 입력 단위

#### 1. 단어

예:

존중

---

#### 2. 살아낸 뜻

예:

존중은  
그 사람의 말을 끝까지 들어주는 것이다

## 근거

### 빈 플랫폼은 작동하지 않는다

살아낸 뜻이 없는 상태에서는

- 검색 결과가 비어 있고
- 질문이 무겁고
- 사용자가 자기 의미를 쓰기 어렵다

먼저 읽을 것이 있어야  
쓰게 된다.

---

### 사전은 기준이고 의미는 삶에서 나온다

사전적 의미는  
표준국어대사전이 제공한다.

뜨읏이 만들어야 하는 것은  
정의가 아니라  
삶에서 나온 의미다.

즉,

사전은 뜻을 설명하고  
삶은 뜻을 만든다.

따라서  
직접 관리해야 할 것은  
사전적 의미가 아니라  
살아낸 뜻이다.

---

### 의미는 짧고 명확해야 한다

초기 입력 단계에서  
맥락, 질문, 태그까지 요구하면  
오히려 기록이 어려워진다.

좋은 의미는  
문득 떠오를 때 빠르게 남겨야 한다.

따라서  
가장 중요한 핵심인

"살아낸 뜻"

하나만 먼저 기록하는 것이 맞다.

---

### 창업자가 첫 번째 사용자다

창업자가 직접 쓰지 못하는 플랫폼은  
다른 사람도 쓰지 않는다.

뜨읏의 첫 번째 사용자는  
사용자가 아니라  
창업자다.

---

### 빠르게 떠오를 때 기록해야 한다

좋은 의미는  
생각해서 만드는 것이 아니라

삶 속에서  
문득 떠오른다.

따라서  
복잡한 관리 시스템보다

빠르게 기록할 수 있는  
가벼운 입력 방식이 중요하다.

## 포기한 대안

### 사용자 입력부터 시작

- 의미 seed가 없음
- 작성 허들이 높음
- 초기 이탈 가능성이 큼

### 대규모 크롤링 기반 수집

- 양은 많지만 결이 없음
- 철학이 흐려짐
- 품질 통제가 어려움

### 사전적 의미 직접 관리

- 유지 비용 증가
- 이미 표준국어대사전이 존재함
- 뜨읏의 본질과 거리가 있음

### 질문 / 태그까지 함께 입력

- 입력 부담 증가
- 기록 지속성이 떨어짐
- 핵심이 흐려짐

## 목표

초기 목표는

### 핵심 단어 30개

각 단어마다

- 살아낸 뜻 3개

를 확보하는 것이다.

즉,

> 최소 90개의 의미 seed

를 먼저 만든다.
