# ADR-PROD-004 결과 화면을 "살아낸 뜻들" 중심 구조로 재정의

## 상태

승인

## 맥락

현재 뜨읏의 단어 상세 화면은 다음과 같은 구조를 가진다.

```
단어
→ 사전적 의미
→ 살아낸 뜻 (대표)
→ 다른 사람들의 뜻 리스트
→ 내 뜻 입력
```

또한 검색 이후 검색창이 사라지고,
"다시 발견하기", "복사하기"와 같은 별도의 버튼을 통해 다음 행동을 유도하고 있다.

하지만 이 구조에는 두 가지 문제가 있다.

첫째, 대표 의미와 다른 사람들의 의미를 구분하는 레이어는 사용자에게 큰 의미가 없다.
사용자에게 중요한 것은 "이것이 대표인가"가 아니라 "누군가는 이 단어를 이렇게 살아냈구나"이다.

뜨읏은 정답을 보여주는 서비스가 아니라 다양한 삶이 같은 단어를 어떻게 만들었는가를 보여주는 플랫폼이다.

둘째, 검색 이후 검색창이 사라지는 구조는 탐색의 흐름을 끊는다.
검색은 별도의 액션이 아니라 항상 가능한 상태여야 한다.

## 결정

결과 화면을 "살아낸 뜻들" 중심 구조로 재정의한다.

### 1. 대표 뜻과 다른 사람들의 뜻 구분 제거

"살아낸 뜻 (대표)"와 "다른 사람들의 뜻 리스트"를 분리하지 않고
하나의 "살아낸 뜻들" 영역으로 통합한다.

### 2. 검색창을 항상 유지

검색 이후에도 검색창을 제거하지 않고
언제든 다른 단어를 탐색할 수 있도록 유지한다.

"다시 발견하기" 버튼은 제거한다.

### 3. 의미가 약한 버튼 제거

- 다시 발견하기
- 복사하기

를 제거한다.

Primary CTA는 "내 뜻 남기기" 하나로 단순화한다.

### 최종 구조

```
[검색창 유지]

단어

사전적 의미

살아낸 뜻들

내게 이 단어는…

[내 뜻 남기기]
```

## 근거

뜨읏은 정답 플랫폼이 아니라 공감 플랫폼이다.

"대표 의미"를 보여주는 구조는 정답이 존재하는 서비스처럼 느껴지게 만든다.
대표를 제거하는 순간 플랫폼은 설명에서 축적으로 이동한다.

검색창을 유지하는 것은 탐색을 버튼이 아닌 상태로 만드는 것이다.
좋은 UX는 "눌러야 보이는 것"보다 "이미 가능한 것"이다.

PoC 단계에서는 모든 UI 요소가 실제 사용자 행동 검증과 연결되어야 한다.
버튼 추가보다 흐름 개선이 우선이다.

## 결과

(운영 후 기록)

- 검색 재사용 비율
- 살아낸 뜻 영역 체류 시간
- 내 뜻 입력 완료율
- 입력 이후 재탐색 비율
- 버튼 제거 이후 이탈률 변화
