# ADR-PROD-005 운영자 전용 Seed 페이지와 Google 로그인 보호 구조

## 상태

승인

## 맥락

뜨읏의 초기 단계에서 가장 중요한 것은 살아낸 뜻의 밀도를 빠르게 만드는 것이다.
플랫폼의 신뢰는 기능보다 이미 존재하는 데이터의 밀도에서 시작된다.

초기 사용자 수가 적은 PoC 단계에서는 익명 사용자의 자연 유입만으로 충분한 데이터를 확보하기 어렵다.
따라서 창업자가 직접 핵심 단어들에 대한 살아낸 뜻 seed 데이터를 지속적으로 작성해야 한다.

## 결정

일반 사용자의 익명 입력 흐름은 유지하고, 운영자 전용 `/seed` 페이지를 별도로 제공한다.

`/seed` 페이지는 Google 로그인 기반으로 보호한다.

접근 조건:
- Google 로그인 완료
- AND 허용된 운영자 이메일 일치

```
Public
- /
- 익명 뜻 입력

Admin
- /seed
- Google 로그인 필요
- 운영자 이메일만 접근 가능
```

Google 로그인은 전체 서비스가 아니라 관리자 보호용으로만 사용한다.

## 근거

일반 사용자에게 로그인 구조를 도입하면 회원가입 → 인증 → 이탈 흐름이 발생하며
서비스 검증 자체가 어려워진다. Public 영역은 익명 유지가 반드시 필요하다.

반면 운영자는 빠르게 많이 입력해야 한다. 이 과정은 일반 사용자 UX와 분리되어야 한다.

Google 로그인을 사용하는 이유:
- 구현이 간단하고
- 운영 비용이 낮으며
- 별도의 인증 시스템 구축이 불필요하기 때문

## 결과

(운영 후 기록)

- 운영자의 seed 작성 속도
- 초기 핵심 단어 데이터 축적량
- 익명 사용자 입력 유지율
