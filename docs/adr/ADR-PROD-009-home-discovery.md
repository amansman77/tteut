# ADR-PROD-009 발견 가능한 뜻(Home Discovery) 기반 탐색 구조

## 상태

승인

## 맥락

현재 뜨읏은 Search-first 구조를 기반으로 동작한다.

사용자는 단어를 검색하고, 그 결과를 통해 다른 사람들이 살아낸 뜻을 발견한다.

하지만 PoC 단계에서는 아직 seed 데이터가 충분하지 않다.

이 상태에서 Search-first 구조만 존재하면 다음 문제가 발생한다.

* 사용자는 어떤 단어가 존재하는지 모른다
* 무엇을 검색해야 할지 떠오르지 않는다
* 검색 결과가 비어 있으면 서비스 전체가 비어 보인다
* 플랫폼 내부에 어떤 결의 의미들이 존재하는지 느껴지지 않는다

검색은 원래 사용자가 이미 찾고 싶은 것을 알고 있을 때 강력하다.

하지만 뜨읏의 핵심 가치는 정답 검색이 아니라
"다른 사람들이 살아낸 의미를 우연히 발견하는 경험"에 있다.

## 결정

홈 화면에 검색창만 제공하지 않고
"발견 가능한 뜻 영역(Home Discovery Layer)"을 함께 제공한다.

검색 이전에 현재 플랫폼 안에 존재하는 의미들을 먼저 보여준다.

### 홈 구조

```
[검색창]

지금 사람들이 살아낸 뜻
[존중] [눈치] [버틴다] [가족] [외로움] [사랑] [기다림]

최근 남겨진 뜻
존중 · "존중은 끝까지 이야기를 듣는 것이다"
어른 · "어른은 무너지지 않는 척 하는 사람이다"
```

### 구성 요소

**1. 검색창 유지**

Search-first 원칙은 유지한다. 검색은 여전히 핵심 진입 UX다.
검색/클릭 시 `/word/[slug]` 페이지로 이동 (브라우저 히스토리 정상 작동).

**2. 살아있는 단어 노출**

`tt_lived_meanings`에서 entry 수 기준 상위 10개 단어를 pill 형태로 노출.

**3. 최근 살아낸 뜻 노출**

최근 등록된 뜻 5개를 단어명과 함께 노출.
"이 플랫폼에는 이런 결의 문장들이 존재한다"는 감각 전달이 목적.

**4. 발견 → 탐색 흐름**

검색 → 발견보다 발견 → 탐색 흐름으로 진입할 수 있도록 설계.

## 근거

### 검색은 질문이 있어야 시작된다

발견 가능한 뜻 영역은 검색 이전에 질문의 힌트를 제공한다.

### 뜨읏은 의미 전시 공간(Semantic Gallery)에 가깝다

단어의 정의를 찾는 서비스보다 "사람들이 그 단어를 어떻게 살아냈는가"를
발견하는 공간에 가깝다.

### 발견은 검색보다 감정적으로 가볍다

어른, 눈치, 버틴다, 외로움 같은 단어는 사용자가 검색하지 않았더라도
감정을 건드릴 수 있다.

### 현재 단계에서는 의미망보다 큐레이션이 우선이다

데이터 밀도가 낮기 때문에 AI 기반 의미 연결보다
운영자 큐레이션과 최근 활동 기반 발견 구조가 우선이다.

## 포기한 대안

- **검색 전용 홈**: 무엇이 존재하는지 알 수 없음, 초기 데이터 부족이 과하게 드러남
- **피드 중심 홈**: 커뮤니티 밀도 부족, SNS처럼 보일 위험, 뜻 발견보다 소비 구조가 강해질 수 있음
- **AI 추천 기반 의미 연결 우선 도입**: 현재 데이터 밀도 부족, 추천 품질 신뢰도 문제

## 결과

검증할 것:

1. 발견 영역 클릭률
2. 발견 이후 word 페이지 전환율
3. 홈 이탈률 감소 여부
4. 사용자의 평균 탐색 깊이
5. 특정 단어의 반복 조회 발생 여부

배울 것:

* 사람은 검색보다 발견에서 더 오래 머무는가
* 어떤 단어가 가장 강한 진입점을 만드는가
* 짧은 문장만으로 공감이 발생하는가
* 뜨읏은 검색 서비스보다 의미 전시 서비스에 가까운가
